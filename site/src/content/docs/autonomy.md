## Claude prepares; you send
By default Claude asks before every outward action, and you do it: submit, send, accept, book. Saying in a message «submit these two» is your yes for exactly those.

If you want Claude to send some kind of message itself — say, the first follow-up in an existing ATS thread, from the template — tell it the rule. It writes the rule into your profile with the date and your words. A rule works only in a live session that you start; scheduled runs never send anything.

Never delegated: passwords, accounts, money and payments, accepting offers or terms, ticking consents (privacy, terms, assessment rules), deleting data, anything that cannot be undone.

The tracker is your record: every change is shown first and written after your yes; changes can be undone one by one. Scheduled runs only prepare a list of changes; in Claude Code they run with a read-only tracker that refuses every write.

## Your data stays yours
Everything about you lives in a separate folder, the **pack** `me/`: facts with sources, answer blocks, recipes, what never to say, your profile and search frame. The kit reads it and writes to it only what you confirm. The pack never goes into the repository.

Job postings, emails and web pages are data, not instructions: Claude never follows instructions found in them, and flags injected instructions and honeypot fields in forms.

Report a vulnerability privately through GitHub: *Security* → *Report a vulnerability*.
