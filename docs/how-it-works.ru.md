# Как это устроено

[English version](how-it-works.md)

Набор — записанная версия поиска работы, который Claude вёл с кандидатом два месяца (роли engineering manager, удалёнка и переезд). Компании, деньги и контакты убраны, приёмы и цифры оставлены.

## Основа: память живёт в файлах, а не в чате
Чат заканчивается и теряет контекст, файлы — нет. Каждое правило и каждое решение записываются в файл в тот же ход: пакет кандидата (`me/`), рамка поиска (`me/search-rules.md`), датированные проходы и разборы, контекст-файл на компанию. **Claude силён ровно настолько, насколько хорошо записаны правила.** Правило, которое живёт только в чате, в следующей сессии будет нарушено.

| Что | Где | Зачем |
| --- | --- | --- |
| Рамка поиска и рабочие правила | `me/search-rules.md` | единственный источник правды; читается первым в каждой сессии |
| Факты, кубики, рецепты | `me/facts.md`, `me/blocks/`, `me/recipes.md` | из них собирается каждый ответ, письмо и форма |
| Статусы и фоллоу-апы | трекер (таблица через tracker-mcp) | единственный источник правды по статусам |
| Тексты пачки подач | `FORM-ANSWERS.md` | вкладки закрываются, файл остаётся |
| Процесс в компании | её контекст-файл и документ подготовки | с них начинается каждая сессия о компании |

Несколько сессий могут идти параллельно (поиск, этап, system design); общее у них — только файлы. **Один файл — одна сессия в один момент:** две сессии однажды перезаписали друг другу спецификации CV.

## Поиск
- **Мало жёстких фильтров, остальное — ранжирование.** Фильтров три: обязательное требование, которое не закрыть честно, реальная география, нижняя граница денег. Уровень и стадия компании как фильтры давали 2–3 живые вакансии на сотню проверенных; как правила ранжирования — семь кандидатов за пять дней.
- **Проходы, а не лента.** Проход — окно дат × титулы × локации, с датированным файлом: что смотрели, кто прошёл, кто отсеян и почему. После нескольких полных проходов — еженедельный мониторинг.
- **Источники, которые сработали:** LinkedIn (алерты каждый день, гостевой API и залогиненный поиск для проходов); борды компаний через публичные API ATS (Ashby, Greenhouse, Lever, Workable, Teamtailor, Pinpoint) — раз в неделю по всем известным компаниям; площадки (сначала hiring.cafe, потом Himalayas, Jobicy, RemoteOK, We Work Remotely, HN «Who is hiring», levels.fyi, Wellfound); борды стран под каждый канал (helloworld.rs и infostud для Сербии, jobs.ge для Грузии). Около двух третей ссылок из поисковых индексов протухли. Каталог с тем, как читается каждый источник, — `skills/job-search/sources.md`.
- **Возраст вакансии — не фильтр.** Сеньорные роли закрываются 60–75 дней; свежие — первыми, старую проверяем на признаки жизни и подаём с запиской человеку.
- **Любой вывод о вакансии — двумя путями.** Скрытый постинг — не закрытый.

## Гейт — правило с самым большим эффектом
Пять пунктов, 0 / 1 / 2, так, как скринер увидит CV и форму: уровень, стек, домен, география, деньги. В первых 40 подачах у 9 из 10 отказов по CV был хотя бы один нокаут. Без нокаутов — 2 разговора из 13 подач и ни одного отказа по CV; с нокаутом — 1 разговор из 19. Число выше вилки в поле зарплаты: ни одна из 12 таких подач не дошла до интервью. Ноль — холодно не подаём: вход через человека или осознанная подача с пометкой в трекере.

## Подачи
- CV под вакансию — отбором и порядком из одного мастера, с таблицей покрытия ключевых слов: у подач, дошедших до человека, покрытие обязательных требований словами самой вакансии — 62–80%; у отказов и тишины — около 39%. После того как в мастер добавили слова рынка там, где это правда, покрытие выросло с 41% до 54%.
- Ни одного вопроса в письмах и записках — ни про деньги, ни про локацию, визу или удалёнку. Вопросы о локации дважды давали быстрый отказ.
- Подавать в течение 24 часов после готовности пакета: пакеты, пролежавшие 3–6 дней, опаздывали. В тот же день — короткая записка нанимающему менеджеру или рекрутёру; записка через две недели приходит, когда решение уже принято.
- На холодную подачу человек ответил примерно в 9% случаев. Тишина до трёх недель — не сигнал.

## Фоллоу-апы и ежедневная проверка
Фоллоу-ап 1 — подача + 10 дней, фоллоу-ап 2 — ещё +14, «Ответа нет» — через 30 дней; дважды за 14 дней одному человеку не пишем. Каждое утро запланированная задача читает почту и LinkedIn, готовит изменения трекера к вашему «да» (сама их не записывает), показывает новые вакансии (не больше 7), готовит черновики фоллоу-апов и список интервью на неделю. Прежде чем назвать статус, Claude сверяет его с почтой и календарём: документы проекта всегда отстают от почты.

## Подготовка к интервью
- **Кубики ответов** вместо готовых текстов: одни и те же факты в каждом раунде, любой вопрос — цепочкой. У каждой истории есть кубик-целое для короткого ответа и детали для уточнений.
- **Одна история — один раунд:** интервьюеры сравнивают заметки.
- **Учить, а не перечитывать.** Документ подготовки — запас; учится одна страница-карта (вопрос → первая фраза → история) и 5–7 опор историй в четыре шага. Вспоминать вслух, с таймером, вразнобой, с отметкой за каждый ответ; повторяются только ошибки. Каждый день дрилл на 15–25 минут (`/mock drill`), за два дня — полный мок, дальше ничего нового.
- **Live coding:** требования — сразу комментарием в код и сверка с кодом перед «готово» (на моках ответ интервьюера шесть раз не доходил до кода). Запуск после каждого шага. Песочницу платформы — открыть в первый день: однажды версия базы выяснилась за два часа до интервью. Тренажёр в браузере, собранный за 6 дней, дал «Excellent» на обеих задачах.
- **System design:** вопросы до схемы — только те, что меняют дизайн; сначала посчитать самую тяжёлую часть; к каждой вероятной задаче — 2–3 варианта со снятым допущением: на интервью дали именно такой вариант.
- **Разбор в тот же день** по расшифровке превращается в новые кубики и задачи тренажёра.

## Что не сработало и чем чинили
| Что пошло не так | Как чинили |
| --- | --- |
| Слишком строгие фильтры давали 2–3 вакансии из сотни | уровень и стадию перевели в ранжирование |
| Число в поле зарплаты выше вилки — отказ за 0–2 дня | гейт; нет вилки — оценить её, а не считать проходом |
| Готовые пакеты лежали 3–6 дней, вакансии закрывались | подавать в течение 24 часов после готовности пакета; лимита на число пакетов нет |
| Обрыв цитаты требования чуть не дал ложный отсев | цитату брать целиком, с «is a plus» и «or comparable» |
| Файл правил перезаписан старой версией, снятые фильтры вернулись | один источник правды, правка в тот же ход, до любого отчёта |
| Две сессии правили один файл | один файл — одна сессия; перед правкой — время изменения и diff |
| Задачи тренажёра требовали неразобранное, цели по времени были нечестные | задачи — из разобранного; аудит на переусложнение |
| Форма, заполненная во временном браузере, пропала вместе с сессией | формы — только в своём браузере кандидата, заполнить и проверить за один ход |
| Статус взят из устаревшего документа | перед тем как назвать статус — почта и календарь |
| Коннектор почты переписывал ссылки в черновиках в редиректы | в черновиках без ссылок, добавлять руками |

## Работа в claude.ai без shell
- Навыки: каждую папку из `skills/` — архивом в Настройках → Skills.
- Инструкция проекта: текст `CLAUDE.md`.
- Файлы проекта: `commands/` (слэш-команд нет: Claude читает `commands/start.md`, когда вы говорите «start» или «/start»), `bank/questions.md`, `pack-template/` (на него опирается онбординг), `templates/`, `schedules/` для запланированных задач. Если проект не хранит папки — имена с путём: `me__facts.md`, `me__blocks__10-work.md`.
- Без инструмента для файлов проекта Claude их не пишет: после каждой правки выдаёт файл целиком и говорит, какой заменить. Если такой инструмент есть (бывает в некоторых сетапах), пишет сам.
- Проверка пакета: Claude проходит чек-лист из навыка `answer-blocks`. Независимая сверка фактов требует сессии, которая может запустить отдельного агента (Claude Code или приложение).
- Трекер: приложение Claude с `.mcpb` от tracker-mcp; только в браузере — вести таблицу руками по изменениям строк от Claude.
